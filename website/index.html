A composite GitHub Action and small Linux eBPF agent for GitHub-hosted Ubuntu runners. Record process and network signals in detect mode, or block non-allowlisted IPv4 egress in defend mode when you're ready to harden the boundary. Every digest leads with a coverage scope line so you know what was observed — and what wasn't — before reading the counts.

Get started View on GitHub

Built for merge gates you can reason about

Linux-only, validated on ubuntu-latest. Telemetry goes to workspace files and the Actions UI — where you already look.

Kernel-adjacent truth

Syscall-class visibility for TCP connects, DNS, TLS ClientHello SNI, filesystem signals, and process relationships.

Progressive hardening

Start in detect mode to baseline normal egress. Switch to defend mode with an explicit allowlist so unexpected IPv4 destinations fail the job instead of silently leaking. IPv6 egress is observed in both modes and surfaces as a warning in the digest.

Honest coverage

Every run writes a Coverage this run line — IPv4 TCP/UDP, IPv6, QUIC/HTTP3, and payloads beyond iov[0] — plus ringbuf-drop totals, so reviewers can tell what the agent didn't see, not just what it did.

CI-native outputs

JSONL event stream, shutdown telemetry JSON, and a compact GFM Markdown digest (≤ ~30 lines, single-row KPI table) that merges into the job Summary — reviewers see the full picture in the PR thread.

Two modes, one agent

Pin a release tag (e.g. coldstep-io/coldstep@v0.3.0) rather than tracking @main. The legacy enforce mode string is rejected — use defend.

Detect

Observe and record. No egress blocking. Ideal for baselining normal traffic and building incident-friendly timelines. IPv6 egress is observed and reported in the digest.

Default

Defend

Block IPv4 egress outside your allowlist via cgroup connect4 / sendmsg4 and BPF LSM where available. Requires a non-empty allowlist. IPv6 egress is observed and surfaced as a warning — defend allowlists are IPv4-only, so any IPv6 destination escapes enforcement and is flagged 🚨 in the digest.

Opt-in

Coverage you can see

Every detect digest now leads with a Coverage this run line and a compact KPI table — so reviewers can tell what the agent observed before deciding what the counts mean.

  • Coverage block One Markdown line per run — e.g. IPv4 TCP/UDP ✓ observed | IPv6 ✗ not observed | QUIC/HTTP3 ✗ not observed | Payloads beyond iov[0]: ✓ observed. Partial-observe paths (split sendmmsg, sendfile, splice) flip the payload state to ⚠️ partial.
  • IPv6 egress (Phase 1) cgroup/connect6 and cgroup/sendmsg6 hooks count non-loopback IPv6 destinations and surface them as ⚠️ in detect or 🚨 in defend. Defend allowlists remain IPv4-only, so IPv6 traffic is reported, not blocked.
  • Ringbuf drops The Full KPI fold shows total ringbuf reserve failures, so you can spot detect-path data loss before treating "zero events" as "zero traffic".
  • sendmmsg multi-message The agent inspects up to vlen=8 messages per sendmmsg(2) call; anything past that bumps the sendmmsg_unobserved_extra counter, which flows into the digest's capture-gaps row.

Artifacts you can diff

All paths default under $GITHUB_WORKSPACE and are overrideable via environment variables such as COLDSTEP_EVENTS_LOG.

  • .coldstep-events.jsonl Append-only event stream — source of truth for investigations.
  • .coldstep-detect.md Compact, GFM-compliant shutdown digest — verdict badge, single-row KPI table, Coverage scope line, and a collapsible Full KPI fold (per-channel counts and ringbuf drops).
  • .coldstep-telemetry.json BPF health totals at shutdown for operational dashboards.

Optional threat enrichment

Layer AlienVault OTX lookups on IPv4 and hostname indicators in detect reports. Set OTX_API_KEY as a repository secret — enrichment is skipped entirely when unset, so fork PRs and repos without the key behave identically.

  • OTX_API_KEY Store as a repository or organization secret. Free account at otx.alienvault.com.
  • If unset No OTX calls, no API usage. Detect jobs still finish successfully.
  • Best-effort Rate limits and errors surface as warnings in the report — enrichment never fails the job. See the detect report docs for schema details.
