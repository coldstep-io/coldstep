## [v0.2.7] — 2026-05-19

### Added
- **P3-1 — KTLS offload detection.** New `raw_tp/sys_enter` probe (`bpf/trace_ktls.bpf.c`) filters on the `setsockopt(2)` syscall NR and emits a ringbuf record (`{tgid, tid, comm[16], fd, direction}`) on every `setsockopt(SOL_TLS, TLS_TX|TLS_RX, …)` call. When KTLS is in use the kernel takes over TLS encryption and the existing userspace ClientHello sniffer only ever sees ciphertext fragments — silently producing low-confidence or zero SNI rows — so this probe makes the structural gap visible. New JSONL event type `ktls_offload` (`telemetry.KTLSEvent` / `EventTypeKTLS`) is signed through the existing Signer path; `telemetry.Summary` gains `ktls_offload_events` and `ktls_ringbuf_reserve_failures` counters; the digest surfaces a `KTLS offload | N sockets · SNI extraction not possible` KPI row (hidden at zero) plus a Technical-details note. The setsockopt syscall NR differs per arch (x86_64=54, arm64=208) so the BPF source uses the `bpf_target_x86` / `bpf_target_arm64` macros and the `tracektls` generator goes through `internal/bpf/bpfgen` to set `-D__TARGET_ARCH_<runtime.GOARCH>`. (#174)
- **P3-2 — TCP connect result events.** Paired kprobe/kretprobe on `tcp_v4_connect` captures the kernel return code (0 on success, negative errno otherwise) and emits a supplementary `tcp_result` JSONL event correlated by `pid_tgid`. The detect digest now renders a **TCP connections** KPI row that splits attempts by outcome — e.g. `18 established · 3 refused · 1 timeout · 2 unreachable` — instead of conflating timed-out / refused connections with established ones. Failure to attach the kretprobe is non-fatal; the entry-side `connect_event` is still recorded and the digest falls back to the legacy "attempt" wording with a footnote pointing at the BPF hook status table. (#175)
- **P3-3 — Inter-syscall TLS ClientHello reassembly.** Some TLS stacks (Go `crypto/tls`, `rustls`, Node.js `TLSWrap`) split the ClientHello across two write / writev / sendto syscalls — a 5-byte record header in one and the handshake body in the next. The single-buffer SNI parser only saw the header and the event was dropped as `tls_sni_parse`. A new userspace per-`(pid,dst,dport)` accumulator (`internal/agent/agent_linux_tls_reassembler.go`) stitches the prefix onto a fresh syscall buffer, retries the SNI parse, and emits the `TLSEvent` with `tls_confidence=partial` and a new `ReassembledSNI=true` field when recovery required multiple writes. Bounded to **512 bytes per key**, **30-second TTL**, and a **1024-key LRU**; non-handshake first bytes evict immediately so `application_data` records can't pin memory. Option A (BPF-side per-socket state keyed on `(pid,fd)`) is the long-term path but is deferred in favor of this userspace fallback for the common header/body split. (#173)
- **P3-4 — Per-row TLS SNI confidence column in the digest.** Additive follow-up to P1-4 (#163), which introduced `telemetry.TLSConfidence`, `ScoreTLSConfidence`, and the aggregate `tls SNI confidence` KPI row. This change makes the per-event tier visible **per row** of the TLS section so operators can attribute KPI numbers to specific destinations. `TLSDigestRow` carries a new `Confidence` field; `writeTLSSection` renders a `Confidence` column that defaults to `unknown` when zero-valued; and `writeKPISemantics` Notes block now includes a 4-tier legend (`full` / `partial` / `inferred` / `unknown`) with the `TLSSNIMaxLen=255` boundary that drives the `full → partial` transition. The legend is gated on `TLSTotal > 0` to match the existing KPI-row gate from P1-4. (#178)

## [v0.2.6] — 2026-05-19

### Security
- **P2-1 — IPv6 Phase 2 (defend enforces).** Defend mode now blocks non-loopback IPv6 egress not on the allowlist. A new `allowed_ipv6` LPM trie (4-byte prefixlen + 16-byte addr) is programmed at startup from AAAA resolutions; `cgroup/connect6` and `cgroup/sendmsg6` consult it and deny with `EPERM` on miss. `::1` (loopback) and `fe80::/10` (link-local) always bypass enforcement. Allowlist compile resolves A **and** AAAA per domain — AAAA-only services are now valid defend allowlist entries. The digest pivots verdict on a new `DefendIPv6AllowlistSize` field: defend + populated + IPv6 observed → ✅ gated; defend + empty + IPv6 observed → 🚨 block-all (with operator guidance). README "IP versions" cell and `action.yml` input docs reflect the dual-stack flow. (#164)
- **P1-1 — DNS allowlist trust model hardening.** Six new telemetry + digest surfaces around the resolved allowlist: end-of-compile `slog.Info` with domain + resolved-IP counts; `MetaEvent.AllowlistIPCount`; per-unresolved-domain warnings + defend-mode aggregate "Allowlist trust model" digest box; compile-time snapshot recorded on `runStats` with a >5 min age info note ("DNS TTLs may have expired"); `scoreWildcardRisk` flagging entries against known multi-tenant shared-infra suffixes (`s3.amazonaws.com`, `githubusercontent.com`, `cloudfront.net`, `blob.core.windows.net`, `azureedge.net`, `r2.dev`, `pages.dev`) with a dedicated digest box; thread-safe per-domain contact counts rendered as a collapsible digest section sorted descending. (#159)
- **P1-2 — Learning-mode poisoning mitigations.** Four post-run gates so a supply-chain compromise landing during the detect recording window cannot silently bake itself into the allowlist. `build-model --min-observation-hours` / `COLDSTEP_MIN_OBS_HOURS` records `observation_hours` + `short_observation_window`; `assert-integrity` hard-fails when the window is shorter than the gate. `model.BuildSuspiciousDomains` flags high-entropy leftmost DNS labels (Shannon > 3.5 bits/char on labels longer than 8 chars), single-observation rare destinations, and port anomalies (HTTP/TLS observation outside `{22, 25, 53, 80, 443, 465, 587, 3000, 8000, 8080, 8443}`); `render-summary` surfaces a `[!WARNING]` block with the per-reason breakdown. `diff --fail-on-new-domain` exits non-zero with a `::error` annotation when previously-unseen FQDNs appear in the current run (bare-IP destinations excluded to avoid IP-rotation churn). New `QUICK_START.md` section "Promoting detect observations to an allowlist" documents the recommended ≥3 builds → strict diff → review → 24h gate workflow. (#160)
- **P1-3 — eBPF safety audit.** Systematic audit of every BPF C translation unit and the Go-side attach sequence: 24 map-lookup null checks, 11 ringbuf reserve/discard pairs, 4 pointer-arithmetic bounds, 1 loop bound (`SENDMMSG_EXTRA_MAX=7`), 5 BTF CO-RE field stability sites, 26 helper-return checks, 1 cgroup attach cleanup, and 2 allowlist TOCTOU sites — all verified clean. One defense-in-depth hardening landed in `bpf/trace_lsm_defend_lsm.inc:lsm_socket_connect`, which now explicitly zero-initializes `family`/`sk`/`protocol`/`daddr`/`dport` so a probe miss fails closed on pre-5.5 kernels, matching the sibling `lsm_socket_sendmsg` path. Inline `AUDIT(5x)` comments make the review visible at every call site. (#162)
- **P1-4 — SNI confidence scoring for TLS events.** New `TLSConfidence` enum (`full` / `partial` / `inferred` / `unknown`) and a `Confidence` field on `telemetry.TLSEvent`. Scoring rule today is a pure function of the parsed SNI string: empty → `unknown`; `len(sni) >= 255` (RFC 1035 boundary) → `partial`; otherwise → `full`. The detect digest gains a `tls SNI confidence` row inside the Full KPI fold (`full=N · partial=M · unknown=K`), gated on `TLSTotal > 0`. `Confidence` is JSON-`omitempty` so older artifacts and report builders continue to work unchanged. (#163)
- **P1-5 — JSONL injection hardening.** New `telemetry.SanitizeField(s, maxLen)` strips C0 controls (U+0000–U+001F), DEL (U+007F), and C1 controls (U+0080–U+009F); replaces invalid UTF-8 with U+FFFD via `strings.ToValidUTF8`; truncates to a per-field byte budget and walks back to a valid UTF-8 rune boundary. Applied at the single decode point per event type (`agent_linux_ring_read.go` for exec / proc_fork / fs_event / tcp / udp / tls / http / bpf_audit, plus the defend deny path) so attacker-controlled `argv[0]`/`comm`, DNS labels, SNI, or HTTP request prefixes can never splice a forged record into `.coldstep-events.jsonl`. Field budgets honor `TASK_COMM_LEN` (16), `PATH_MAX` (4096), RFC 1035 FQDN (253), and longest HTTP verb + slack (16). New unit + fuzz tests assert JSON-marshalability, no surviving control bytes, byte-budget honored, valid UTF-8. (#161)
- **P0-1 — IPv6 egress detection (Phase 1, observe-only).** Two new BPF programs (`cgroup/connect6`, `cgroup/sendmsg6`) plus matching per-cpu counters surface IPv6 destinations that previously produced zero JSONL events and zero digest warnings. `verdictEmoji` flips to ⚠️ on any non-zero IPv6 counter in detect mode and to 🚨 in defend mode (the IPv4-only allowlist could not gate the connection). `::1` (loopback) is filtered in BPF so localhost IPv6 traffic doesn't dominate counters. Graceful degradation: missing programs on older kernels log at `slog.Info`; the IPv4 defend path is unaffected. Superseded by P2-1 (#164) for the defend enforcement half. (#155)
- **`lsm/socket_sendpage` — close the sendfile/splice egress gap on kernel 5.15.** On 5.15, `sendfile(2)` and `splice(2)` reach the socket via `sock_sendpage()` → `security_socket_sendpage()` rather than `sendmsg`, so neither `cgroup/sendmsg4` nor `lsm/socket_sendmsg` could gate them. A new `lsm/socket_sendpage` hook runs the same IPv4 allowlist + ignored-net + deny-event flow, with a `sendpage_observed` PERCPU_ARRAY counter so userspace can see how much sendfile/splice traffic crossed the hook. On kernel 6.8+ the sendmsg path covers `sendfile`/`splice` via `MSG_SPLICE_PAGES`, so the new hook is redundant but harmless. (#157)
- **Pre-check kernel BTF for `socket_sendpage` LSM hook.** The defend loader now probes the kernel's BTF for the `socket_sendpage` LSM type before attempting to load the program, so kernels that ship `CONFIG_BPF_LSM` without the `sendpage` hook degrade cleanly to the IPv4 sendmsg path instead of failing prog_load. (#158)
- **P0-2 / P0-3 — Coverage scope block + ringbuf drop visibility.** Every digest now emits a one-line Coverage statement (`IPv4 TCP/UDP ✓ observed | IPv6 ✗ not observed | QUIC/HTTP3 ✗ not observed | Payloads beyond iov[0]: <state>`) so a ✅ Clean run badge no longer implies complete observation. The `Payloads beyond iov[0]` cell flips to `⚠️ partial` when any BG-01 partial-observe counter fired this run; when partial-coverage signals are present, the heading emits an extra blockquote subtitle steering the reader to the block. Aggregate ringbuf-drop row surfaces in the Full KPI table when the detect-path sum is non-zero. (#154)

### Added
- **P2-2 — QUIC/HTTP3 observation heuristic.** UDP/443 egress was previously logged as a plain `udp` event with no signal that the underlying HTTPS-equivalent path was opaque to the BPF probes (QUIC encrypts at the transport layer; payload sniff is not possible). `internal/agent/quic_candidate.go` adds a userspace heuristic `IsQUICCandidate(dstIP, dstPort)` — fires when `dstPort == 443` AND `dstIP` parses as non-loopback IPv4 — and the UDP ring reader now emits a synthetic `quic_candidate` JSONL line (`telemetry.EventTypeQUICCandidate`) alongside each matching `udp` event. New `QUICCandidateCount` field on `DigestInput`; a `QUIC (port-443 UDP)` KPI row renders when non-zero with `N flows · payload not inspected` wording plus a Technical-details bullet explaining the encryption gap. No BPF C source, no `go generate`, no `telemetry.Summary` field, no `action.yml` input. (#167)
- **P2-3 — Runner compatibility matrix CI + agent startup probe.** New weekly `coldstep-runner-compat.yml` (Mon 04:00 UTC + dispatch) exercises four sibling jobs (`vanilla`, `dind`, `buildkit`, `service-containers`), each `continue-on-error: true` so one broken variant doesn't cancel the rest; an `aggregate` job converts per-variant outcomes into a single pass/fail summary table. Agent-side: `CheckRunnerCompat()` (`internal/agent/compat_check_linux.go`) returns non-fatal `[]telemetry.CompatWarning` with stable codes — `cgroup_v1_detected`, `cgroup_namespace_nondelegated` (detected from `/.dockerenv` + host-prefixed `/proc/1/cgroup`), `deep_cgroup_nesting` (depth ≥ 4), `container_cgroup_detection_failed`. Warnings are logged via `slog.Warn("runner_compat_warning", ...)` and surfaced in `telemetry.Summary.CompatWarnings`. Always non-fatal: detect mode proceeds regardless. (#166)
- **P2-4 — Kernel coupling regression harness + BTF startup probe.** `internal/agent/btf_probe.go` wraps `btf.LoadKernelSpec` with a named, actionable error (`kernel BTF unavailable (requires kernel 5.5+ with CONFIG_DEBUG_INFO_BTF=y): ...`); the agent calls it early in `Main` and aborts startup with `slog.Error(..., "btf_available", false, ...)` on failure rather than letting CO-RE relocation fail cryptically at `prog_load`. The positive signal surfaces on a synthetic `{Name: "btf", OK: true, BTFAvailable: true}` row in `bpfSt` so `.coldstep-telemetry.json` parsers that already iterate the `bpf` array see it for free. New `BTFAvailable` field on `telemetry.BPFStatus` (omitempty). New `.github/workflows/coldstep-kernel-matrix.yml` workflow (weekly Mon 03:00 UTC + dispatch) runs build + unit + integration over a 5.15 / 6.1 / 6.6 / 6.8 matrix — today every row runs on the host `ubuntu-latest` kernel; the workflow is documented as the scaffold a future qemu/vmtest harness drops into. The reusable CI runner additionally annotates a warning when the runner kernel drifts >2 majors past the 5.15 floor. (#165)
- **P2-5 — Reputation integration hooks.** Stable, extensible plug-in interface under `internal/reputation` so external integrators can ship IP-reputation enrichers without modifying core coldstep. `Enricher` interface, `Result` struct, `NoOpEnricher`, `Register`/`Registered`/`EnrichAll` with concurrent fan-out, deterministic name-sorted output, and ctx-deadline guard so a hung backend cannot block its peers. Ships an OTX backend (`X-OTX-API-KEY`, 10s timeout, 4 MiB JSON cap, 0–10 score derived from pulse count) and a CIRCL PassiveDNS stub. `internal/reputation/loader` is env-driven (`COLDSTEP_OTX_API_KEY`, `COLDSTEP_VIRUSTOTAL_API_KEY`, `COLDSTEP_PASSIVEDNS_SERVER`); empty env vars install a `NoOpEnricher` so the returned slice shape stays stable. `coldstep-report` `rdns-enrich` and `otx-enrich` invoke the loader after their existing work, writing combined results into `m["reputation_results"]` plus an `m["reputation"]` summary. Enrichment is **post-processing only** — runs after JSONL is on disk, never on the agent's hot path. Coexists with the legacy `OTX_API_KEY` flow (different env var). (#168)

### Changed
- **Compact GFM-compliant Step Summary digest.** Job Summaries render GitHub Flavored Markdown (standard Markdown plus a narrow HTML subset: `<details>`, `<summary>`, `<br>`, `<hr>`, `<table>`); anything outside that subset rendered as literal text. The previous digest used `<font color="">`, `<p align="center">`, `<sub>`, and `<center>` — all four are now gone. The visible portion of the digest is roughly 19 lines for a typical detect run (test-enforced budget: 30): a `## <emoji> coldstep — <mode>` headline, a one-row 5-column KPI table, top-10 destinations, a triage table with only rows that have something to say, and a footer pointer to `.coldstep-events.jsonl`. Everything else (full per-channel KPI table, defend section, run info, per-protocol event tables, BPF hook status, KPI semantics) lives inside a single `<details>` "Technical details" fold; each per-protocol event table is its own nested `<details>` so operators can drill into one protocol without scrolling past the rest. Pure presentation change; no `DigestInput` / `telemetry.Summary` shape change, no agent or BPF code touched. (#152)
- **Complete PERCPU_ARRAY migration for hot-path counters.** Seven observability counters were still `BPF_MAP_TYPE_ARRAY` + `__sync_fetch_and_add` despite the project's documented convention (PERCPU_ARRAY for no global atomic contention): `udp_sendmsg_multi_iovec_observed`, `tls_writev_multi_iovec_observed`, `unobserved_egress_syscalls_observed`, `io_uring_setup_observed`, `dns_recvfrom_buf_update_failures`, `tcp_dns_responses_observed`, `tcp_dns_skipped_short_read`. Converted to `BPF_MAP_TYPE_PERCPU_ARRAY` with plain `(*v)++` on hot syscall paths (every UDP sendmsg, io_uring_setup, TLS writev, DNS recvfrom). Go reader swapped six callers from `readUint32CounterMap` → `readUint32PerCPUArraySum`; deleted the now-unused scalar helper and its tests. Not a correctness bug — `__sync_fetch_and_add` is atomic-safe — but eliminates cache-line bouncing on hot paths. Also pins `securego/gosec` to a SHA (`v2.26.1`). (#139)
- **Go Tier-1 simplifications (~219 LOC removed).** Pure refactor across agent, report, policy, config, and action layers — no behavior change. Drops 17 thin BPF counter-read wrappers (`readDenyReserveFailureCount` and friends) that only nil-checked `*Objects` and forwarded to existing helpers. Factors `loadDefendMaps` + `loadLSMDefendMaps` into one `loadDefendMapsForBackend` parameterised by a `defendMapSet`. Collapses four identical `*EmptyReason` digest helpers into a single `sectionEmptyReason(degraded, readerErrors)`. Dedupes comma + whitespace token splitters in `internal/policy/ignore.go` and `cmd/coldstep-action/allowlist_files.go`. Consolidates domain normalisation into `internal/policy.NormalizeDomainsFromRaw` (`internal/config` deletes its copy). Drops the redundant explicit legacy-mode rejection branch — the "mode not in {detect, defend}" check already covers it. (#141)
- **BG-03 — `sendmmsg` multi-message observation up to `vlen=8`.** `traceconnect` now observes every message in a `sendmmsg(2)` batch up to `vlen=8` instead of only the first; the existing `sendmmsg_first_only` counter still fires when `vlen > 8` so the partial-coverage signal stays accurate. (#153)

### Fixed
- **`io-uring-disable` now actually disables io_uring.** Both `src/start.ts` and `cmd/coldstep-action/main.go` invoked `sudo sysctl -w io_uring_disabled=2`, but sysctl rejects the bare key with `error: "No such file or directory"`. The correct fully-qualified key is `kernel.io_uring_disabled`. The Go path also swaps the silent `_ = exec.Command(...).Run()` discard for `CombinedOutput()` + a GitHub Actions `::warning::` annotation on failure, so future breakage (older kernels without the sysctl, sandboxed runners) is visible in the job log instead of swallowed. (#151)

## [v0.2.5] — 2026-05-18

### Added
- **HTTP/1 sniff parity for write(2) family** — plaintext HTTP/1 requests on dport 80 are now captured when emitted via `write(2)`, `writev(2)`, `pwrite64(2)`, `pwritev(2)`, or `pwritev2(2)` on a connected TCP socket. Previously only the `sendto(2)` arm produced `http_events`; Go `net/http`, libcurl over plain HTTP, and most stdlib HTTP clients use `write(2)` and were silently missing from the HTTP JSONL stream. The new dispatch helper fetches the (tgid,fd) tuple once and runs both the TLS-ClientHello sniff and the HTTP/80 sniff from a single LRU lookup, keeping the verifier budget flat. (BG-04)

### Changed
- **Detect digest redesign** — the `.coldstep-detect.md` / Job Summary digest now leads with a one-line headline status badge (🚨 Alert / ⚠️ Review / ✅ Clean run), surfaces the hot-egress table before the triage ribbon, reorders the KPI table to network → process → fs → health with ringbuf-reserve and multi-iovec rows directly under their parent metric, and collapses the long-form KPI prose / standalone BPF hook table / Footnotes block into a single `<details>` "Technical details" fold plus a small Run info table. ⚠️ (with VS-16) is now used consistently for warning rows. Pure presentation change; no `DigestInput` / `telemetry.Summary` shape change, no agent or BPF code touched. (#149)
- refactor: consolidate four `*EmptyReason` digest helpers into `protocolEmptyReason`.
- **BPF telemetry — per-syscall partial-observe counters (BG-01).** Replaced the dead aggregate `unobserved_egress_syscalls_observed` ARRAY (no increment sites since the pwrite* sniff arms were added; always read 0) with a 4-slot `partial_egress_observed` PERCPU_ARRAY. Slots: `sendfile`/`sendfile64`, `splice`, and `sendmmsg` (first-message-only). The digest, triage ribbon, and telemetry JSON now surface each path independently (`sendfile_observed`, `splice_observed`, `sendmmsg_first_only`) so operators can see *which* syscall drove the visibility gap instead of a single total. Existing sniff paths are unchanged.
- **BG-02: bounded multi-iovec sniff** — When `writev`/`pwritev`/`pwritev2` is called with `vlen >= 2`, or `sendmsg`/`sendmmsg` is called with `msg_iovlen >= 2`, the BPF agent now performs a single additional bounded `bpf_probe_read_user` of `iov[1]` and feeds it through the existing TLS ClientHello and HTTP request fingerprint helpers. Previously only `iov[0]` was inspected, and any TLS/HTTP content fragmented into `iov[1]` (e.g. header-then-body framing) was silently dropped from `tls_events` / `http_events`. Strictly capped at index 1 — no unlimited iov walk. The `tls_writev_multi_iovec_observed` and `udp_sendmsg_multi_iovec_observed` counters continue to fire so the historical fragmentation-rate metric stays comparable.
- BG-03: `sendmmsg_multi_message_observed` counter tracks NR_SENDMMSG calls with vlen>1 (separate from multi-iovec counter)

## [v0.2.4] — 2025-05-16

### Fixed
- **cgroup root-attach** — BPF programs now attach to `/sys/fs/cgroup` (the cgroup v2 unified-hierarchy root) instead of a sub-cgroup derived from `/proc/self/cgroup`. On GitHub-hosted `ubuntu-latest` runners, job-step processes run in sibling or parent cgroups relative to the coldstep agent (which executes via `sudo`). Attaching to a sub-cgroup left those steps unprotected — the root cause of defend-mode blocking zero connections despite BPF programs loading successfully. Fixes #122.

### Changed
- **Runtime SHA256 verification** — removed the hardcoded `COLDSTEP_BINARY_SHA256` constant from `src/shared.ts`. Go binaries are not reproducible across CI runs, so a hardcoded SHA drifted after every `supply-chain-attest` build. The pre-step now fetches the expected digest at runtime from the GitHub Releases API (`asset.digest` on `GET /repos/coldstep-io/coldstep/releases/tags/{version}`), eliminating the mismatch cycle.

### Verified
- Defend-mode lab: 0 of 3 attack simulations reached the signal server (env exfil, DNS exfil, credential scan — all blocked).

## [v0.2.1] — 2025-04-30

### Added
- Initial public release.
- Linux eBPF agent with eight BPF probe packages: `traceexec`, `tracefork`, `traceconnect`, `tracedefend`, `tracelsmdefend`, `tracedns`, `tracefs`, `tracebpfaudit`.
- Two runtime modes: `detect` (observe-only telemetry) and `defend` (cgroup `connect4`/`sendmsg4` + BPF LSM `socket_connect`/`socket_sendmsg` for IPv4 egress blocking). The spelling `enforce` is explicitly rejected at startup.
- `coldstep-action` binary (`start`/`stop`) for composite Action lifecycle management.
- `coldstep-report` post-run pipeline: `build-model`, `assert-integrity`, `render-summary`, `render-html`, `diff`, `rdns-enrich`, `otx-enrich`, `render-ip-summary`.
- Workspace artifacts: `.coldstep-events.jsonl` (append-only event stream), `.coldstep-detect.md` (Markdown shutdown digest), `.coldstep-telemetry.json` (BPF health totals), `.coldstep-ready.json` (readiness probe).
- Optional AlienVault OTX enrichment for detect HTML reports when `OTX_API_KEY` is set; skipped silently when unset.
- Composite GitHub Action (`action.yml`) with inputs: `mode`, `allow`, `allow-file`, `detect-profile`, `report`, `fail-on-error`, `signing-key`, `log-level`, `ignored-nets[-file]`, `bootstrap-allowlist`, `ready-timeout-seconds`, `github-token`.
- CI gates: `gofmt`, encoding scan, unit tests (amd64 + arm64 matrix), integration tests (root + BPF), action bundle, detect-mode and defend-mode lab runs.
- BPF C unit tests (`bpf/host_test/`) via `scripts/run-bpf-c-unit-tests.sh`.
- `COLDSTEP_DETECT_PROFILE=enhanced` enables `proc_tree`, `tls_sni`, and `fs_events` streams by default.
